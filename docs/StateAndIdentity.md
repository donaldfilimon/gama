# State, identity and ownership

`Host(App).create(allocator, &app)` allocates a stable owner. Destroy it once; application storage, allocator and subscribed Signals must outlive it. Zig does not enforce Swift noncopyability or Sendable. Never copy initialized owners or forge their bookkeeping fields. Publicly inspectable owner fields are restricted machinery; checked methods are the mutation interface.

`BuildContext.state(T, slot, initial)` returns a generation-checked handle keyed by NodeID and slot. Owned values supply clone/deinit hooks. Successful writes clone before replacement; OOM preserves the previous value. Reads borrow until a successful write, type replacement, removal or owner destruction. Raw cached pointers are not generation-checked. Removed state is swept only after successful publication.

Positional children retain positional state. Use stable identified scopes when state must follow reordered elements. A Signal is explicitly shared; hosts subscribe and cancel through owner-managed tokens. Two hosts have independent per-surface state. Rendering may reconcile focus and rebuild once; actions use the previous published registrations until commit.

Every PreparedFrame token is consumed once by commit, abort, or finish/deliver. Failed rendering retains the last frame; accepted model input remains accepted. Native handles check executor and reentry. Freestanding users guarantee one executor. Host-owned borrowed output expires at the next successful publication or owner destruction.

`complete` and `emit` admit submissions while the host is idle or dispatching a live action, key handler or lifecycle callback. These narrow channels preserve native executor checks; recursive prepare, handle, invalidate, acknowledgement, drain and destroy remain rejected. Admission is suspended during outcome allocation/free, and internal rendering, capture clone/deinit, active store mutation, observed Signal clone/deinit and owner teardown reject submissions. An app-owned Signal observer follows the same rule: idle/live-callback submission is allowed, but a signal-backed Store write remains an active store mutation, so its observers must defer submission until that write returns. Signal snapshot lifetime checks still prevent owner destruction.

Completion clones its message before accepting the first result; later submissions do not replace or invalidate it. The borrowed message lasts until host destruction. Emission clones each line and appends only after all required allocation succeeds; OOM leaves the queue unchanged. The outer pending-lines slice expires on queue mutation; individual line bytes expire on acknowledgement, drain ownership transfer or host destruction. Successful submission marks the next frame dirty. Failed transport retains its unacknowledged prefix for retry; acknowledgement consumes only the count actually delivered.
