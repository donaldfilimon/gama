# Capability evidence

Status is evidence-based, not inferred from source presence.

## Status vocabulary

- **Implemented** — the code exists and compiles in at least one local
  configuration; no runtime proof is claimed.
- **Locally proven** — a check script or test suite passes on the pinned
  toolchain on this machine; not yet (or not currently) backed by CI.
  Qualified forms **narrow** this and are deliberate, not drift: *locally
  compile proven* means it builds but nothing ran, *locally cross-compile
  proven* means it builds for another triple, *locally runtime proven* means
  a binary or host actually executed, and *locally compile/test proven* means
  both. Read a qualifier as a restriction on the plain word, never as an
  upgrade of it.
- **Hosted proven** — the claim is enforced by a required job in the hosted
  "Gama acceptance" matrix.
- **Provisional** — behavior exists but a design decision that could change
  it is still open (see the current work in `tasks/todo.md` and the relevant
  accepted or draft specification).
- **Blocked** — proof is impossible right now for a stated external reason
  (for example, no Windows 6.5-dev snapshot); never described as shipped.
- **Unverified** — the last proof predates changes to the files the row
  depends on. Both the last proof commit and the fact of the invalidating
  change are recorded, and no stronger claim may be made until a new run
  passes. This is the honest state a claim enters the moment its dependencies
  move; `scripts/check-evidence-freshness.sh` fails a row that declares it
  without real drift, so it cannot be used as a parking space.
