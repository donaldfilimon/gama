# Portable benchmark

Run `zig build bench -Doptimize=fast -- --runs 5 --frames 2000 --warmup 200`. The fixed BenchApp tree contains the styled header, left alpha/bravo/charlie/delta/echo border, right three-button/status border, and styled footer from the historical portable workload. Each run starts a fresh host and 80×24 buffer, then dispatches did_launch. The eight-event script is Tab, Tab, Enter, pointer press at (12,4), release, BackTab, x, Escape. No initial pump precedes the first Tab. Warmup advances the same script.

Dispatch and supported host invalidation occur before fixed paint timing: the old harness rendered every frame, while the new host normally dirty-gates. Paint includes prepare/layout, clearBack, painting and commit. DrawList.from and ANSI presentDiff are independently timed; result-count use is outside those fixed timers. Resize alternates 160×48 then 80×24 for max(1,frames/20), with no events or warmup; resize/paint/present and byte-count use are timed together. Default color depth remains unknown.

Samples pool across runs. Median is sorted[count/2] (upper middle); p95 is nearest rank ceil(count*0.95)-1. Defaults produce 10,000 samples per fixed phase and 500 resize samples. CLI rejects missing/noninteger/negative/out-of-bound limits, strengthening the historical fallback behavior. Runs are bounded to 1…100, frames 1…100000, warmup 0…100000.

A new FNV-1a content digest hashes fixed-frame wire/ANSI output and resize ANSI bytes outside timing, including warmup, and requires equal runs. The historical portable harness had no seed, digest or binary-codec phase. Encoding for the new digest is outside the retained phases. Memory accounting here identifies allocator boundaries; it does not measure process RSS or allocation counts. Framework allocations remain in their phases, harness sample/digest work outside. Apple raster/autorelease benchmarks are retired. [Capabilities](Capabilities.md) records actual conditions and measurements; no relative speed claim is made.
