# Gama Studio: wire the RealityKit viewport (Phase 2, first editor slice)

## Context

Gama Studio (`~/dev/active/gama-studio`, local-only, `main`) has its authoring core (`GamaAuthoring`: document, commands, `EditorSession`, change feed) and an Apple-only `RealityBridge` (`GamaReality`) that projects the document into a RealityKit tree. Gama now has native regions: `NativeRegion` plus `GamaHostView.attach(_:to:)`, on PR #108, head `2ef325c120674cfe218de44f492f435ff50a28e7`, which stacks on #107. Donald asked to wire the RealityKit viewport into Studio: a macOS window whose editor panels are Gama views, with a live RealityKit viewport in the middle, both driven by the same command bus (spec invariants 3 and 4: UI mutates only through commands).

The survey of gama at `2ef325c` settled the approach:
- **The window.** An external package can't reach `GamaShell`'s host view (`GamaShellWindowController.hostView` is `package`). Studio therefore owns its `NSWindow` and `GamaHostView(frame:)`. It calls `install(app:)` (public, takes a `sending` app value, installs only the primary scene) and then `attach(arView, to: NativeRegionID("viewport"))`.
- **Redraws.** `App.connect` is never called on the Apple host. Button actions already mark the frame dirty, and out-of-band changes use `hostView.invalidate()`.
- **The dependency.** Gama's only dependency is swift-syntax, pinned by revision, so Studio must depend on gama by `revision:`. The `unsafeFlags` in gama's package live only in WASM executable targets that Studio doesn't use. Studio already pins the same compiler snapshot.
- **A peer session touched Studio.** Its HEAD is `8dbff3e` ("docs: gate command uses >|…"), which this session did not make.

## Decisions (defaults taken; each is cheap to change)

- **Dependency:** `.package(url: "https://github.com/donaldfilimon/gama.git", revision: "2ef325c120674cfe218de44f492f435ff50a28e7")`, using products `GamaCore` and `GamaAppleUI`. After #108 merges, bump to a `main` revision. A local path to the iCloud checkout is rejected because iCloud stalls and has codesign traps.
- **Platform:** macOS only for this slice. `GamaStudioEditor` wraps its files in `#if canImport(AppKit)`, so other platforms still compile.
- **Concurrency:** `StudioModel` is `@MainActor`. Gama `Button` actions are plain `() -> Void` closures that run on the main actor inside the host, so they reach the model through `MainActor.assumeIsolated { … }`, which asserts at runtime rather than assuming silently.

## Targets and files

- **`Sources/GamaStudioEditor/`** (library, `strictLibrary`, depends on `GamaAuthoring`, `GamaReality`, `GamaCore`, `GamaAppleUI`):
  - **`StudioModel.swift`** (`@MainActor final class`) owns an `EditorSession` and a `RealityBridge`. Every mutation goes through `run(_ command:)` or `transaction`, followed by `bridge.apply(session.drainChanges(), from: session.document)`. It provides:
    - `undo()` and `redo()`
    - `select(_:)`
    - `addPrimitive(_:)`, which creates the entity with a transform and material, parents it at the root, and selects it
    - `deleteSelection()`, `duplicateSelection()`, `nudgeSelection(by:)`, `toggleVisibility()`
    - `lastError: AuthoringError?`, set when a command is refused and shown in the status line
    - a `sampleScene()` factory: ground plane, box, sphere, cone
  - **`StudioApp.swift`:** `struct StudioApp: App`. It holds `let model: StudioModel`; `init()` builds a sample model, because `App` requires `init()`. It has one `Window("Gama Studio", id: "main", role: .primary)`, laid out as:
    - Toolbar `HStack` of `Button`s: Add Box, Add Sphere, Add Cone, Duplicate, Delete, Undo, Redo.
    - Body `HStack`:
      - hierarchy panel (`VStack`, `.frame(width: 26)`, `.border(title: "Scene")`): `IdentifiedForEach` over the document in depth-first order, indented by depth, one `Button` per entity that selects it; the selected row is highlighted
      - `NativeRegion(NativeRegionID("viewport")) { Text("3D viewport — RealityKit on macOS") }.frame(maxWidth: .max, maxHeight: .max)`
      - inspector panel (`.frame(width: 30)`, `.border(title: "Inspector")`): the selected entity's name, position, mesh, material and visibility, with nudge buttons ±X/±Y/±Z and a visibility toggle
    - Status line: revision, selection, undo label, and the last refusal.
  - **`ViewportController.swift`** (`@MainActor`) builds the `ARView(frame:)`:
    - adds an `AnchorEntity(world: .zero)` holding `bridge.root`, plus a `PerspectiveCamera` looking at the origin and a `DirectionalLight`;
    - handles click-to-pick: an `NSClickGestureRecognizer` calls `arView.entity(at:)`, walks up to the nearest entity with `bridge.id(for:)`, then calls `model.select` and `hostView.invalidate()`.
- **`Sources/gama-studio/main.swift`** (executable `gama-studio`, `strictCore`):
  - Sets up `NSApplication` with `.regular` activation, a Quit menu and an app delegate.
  - Creates an `NSWindow` of 1280×800, with `GamaHostView(frame:)` as its `contentView` and autoresizing on.
  - Calls `install(app: StudioApp(model:))` and `attach(viewport.arView, to: "viewport")`.
  - `--smoke` finishes launching without running the event loop. It pumps one frame (`hostView.invalidate()`), asserts `currentDrawList.commands.count > 0`, the `ARView` is a subview, its frame is non-zero and not hidden, and the bridge holds the sample entities. It exits 0 or 1.
  - `--snapshot <png>` renders the `ARView` through `snapshot(saveToHDR:)` after one run-loop turn, then exits. This is best effort, for visual evidence.

## Collision for picking

`ARView.entity(at:)` needs a `CollisionComponent`. Add it in `RealityBridge.project`, beside the `ModelComponent`: one collision shape per primitive (box, sphere and capsule/convex as available). Remove it whenever the mesh is removed. It's a projection of the mesh, so it stays within ADR 0002, and gets one line added there. The exact `ShapeResource` generators are checked against the SDK interface (`RealityFoundation` swiftinterface) before use. Convergence tests extend their snapshot with "has collision".
