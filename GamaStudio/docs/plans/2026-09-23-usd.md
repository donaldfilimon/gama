# Gama Studio: USD save and load

## Context

Gama Studio (`~/dev/active/gama-studio`, main `438bdad`, 133 tests) authors a value `SceneDocument` of entities with transform, mesh, material, visibility, light, and camera components, but it cannot persist anything. The spec (`docs/spec/2026-09-23-unified-usd-realitykit-spec.md`) names USD as the interchange format. Donald asked for USD save and load.

Measured on this machine (2026-09-23): Apple USD Tools 0.25.11 are in `/usr/bin` (`usdcat`, `usdchecker`, `usdzip`). A hand-written USDA using `Xform`, `Plane`, `Cone`, `DistantLight`, `SphereLight` with `ShapingAPI`, `Camera`, `visibility`, `xformOp:translate/orient/scale`, and `custom int gama:id` passed both `usdcat` and `usdchecker` ("Success!").

A second probe also passed `usdchecker`. It carried:

- `customLayerData` with quoted `"gama:…"` keys;
- a `Cube` with `prepend apiSchemas = ["MaterialBindingAPI"]` and `rel material:binding`;
- a `Material` with `outputs:surface.connect` pointing at a `UsdPreviewSurface` `Shader`.

`usdcat` then **reformats** that file. It reorders attributes, breaks metadata across lines, and shortens float text (`0.30000001` becomes `0.3`, which parses to the same `Float`). The reader must therefore accept that reformatting, and the gate compares documents, not the text `usdcat` emits.

Already present, so reuse rather than add: `RealityBridge.rebuild(from:)` (`Sources/GamaReality/RealityBridge.swift:40`), `EditorSession.init(document:)` (`EditorSession.swift:26`), and the main menu built in `Sources/gama-studio/main.swift:47-57`, which currently has only an App menu.

## Decisions (made, not asked; flip conditions noted)

1. **Own USDA writer and reader, stdlib-only, not `Entity.write(to:)` or ModelIO.** RealityKit export writes RealityKit's own scene, not our authored document: it loses entity ids, primitive kind, lights, cameras, and editor visibility, and it cannot read anything back. Our own codec round-trips losslessly and stays testable without a GPU. *Flip if:* Donald wants arbitrary third-party USD import. That is a separate phase that needs a real USD parser.
2. **Standard schemas first, plus `gama:` attributes as the authority.** External tools see real USD: gprims, UsdPreviewSurface, UsdLux, UsdGeomCamera. On load, `gama:` attributes win whenever they are present, which keeps the round trip exact where USD semantics differ. The clearest case is light intensity: Gama stores lux or lumens, while UsdLux uses its own intensity/exposure model.
3. **Format: `.usda` text only.** `.usdz` needs zip and would add nothing for a text round trip. It is Proposed.
4. **Load replaces the document and is not undoable.** The load clears undo history and selection. ADR 0005 records this.
5. **UI: a File menu with Open… ⌘O, Save ⌘S, and Save As… ⇧⌘S**, driven through `NSOpenPanel` and `NSSavePanel`. There is no toolbar button, so the toolbar focus order stays unchanged. For the gate there are also CLI flags: `--open <path>` loads at launch, and `--export <path>` writes and exits.
6. **Reader scope: files Gama wrote, or the same content reformatted by `usdcat`.** Unknown prim types, unknown `gama:` versions, and malformed input all fail with an explicit `USDError` carrying a line number. Nothing is silently skipped.

## Mapping (writer → USDA; reader inverts)

- **Stage metadata:** `defaultPrim`, `metersPerUnit = 1`, `upAxis = "Y"`, and `customLayerData = { int "gama:formatVersion" = 1; string "gama:nextEntityID" = "<n>" }`.
- **Entity → prim, named from the entity name.** Names are sanitized to `[A-Za-z_][A-Za-z0-9_]*`; collisions get `_<id>`, and an empty name becomes `Entity_<id>`. The exact name goes in `custom string gama:name`, the id in `custom uint64 gama:id`. Children nest in authored order. Several document roots become sibling root prims, and `defaultPrim` is the first one.
- **Prim type from the components:**
  - mesh box → `Cube` (`size = 1`)
  - sphere → `Sphere` (`radius = 0.5`)
  - cylinder / cone → `Cylinder` / `Cone` (`height = 1`, `radius = 0.5`, `axis = "Y"`)
  - plane → `Plane` (`width = 1`, `length = 1`, `axis = "Y"`)
  - these match `PrimitiveMeshes` unit sizes
  - light directional → `DistantLight`; point → `SphereLight` with `treatAsPoint = 1`; spot → `SphereLight` with `ShapingAPI`
  - camera → `Camera`
  - otherwise `Xform`
  - An entity with several prim-typed components (for example the sample Camera, which has both a light and a camera) becomes an `Xform` holding child prims named `GamaMesh`, `GamaLight`, and `GamaCamera`, each marked `custom bool gama:component = 1`. The reader folds these back into the parent entity. **This is the one structural rule the tests must pin.**
- **Transform:** `xformOp:translate`, `xformOp:orient` (quatf, stored w-first as USD requires), and `xformOp:scale`, plus `xformOpOrder`. The transform is omitted when it is identity and the entity had no transform component; `gama:hasTransform` distinguishes identity from absent.
- **Determinism:**
  - Walk `roots` and `children` in authored order.
  - Emit components in `ComponentKind` order; component-child prims follow the same order (`GamaMesh`, `GamaLight`, `GamaCamera`).
  - Reserve the names `Looks`, `GamaMesh`, `GamaLight`, and `GamaCamera` before sanitizing sibling entity names, so a real child named `GamaMesh` gets the `_<id>` suffix.
  - Write one `Material` prim per entity, named `M_<id>`, under a single `Looks` scope placed as the last child of the first root.
  - Attach the `MaterialBindingAPI` schema wherever a binding is written.
- **Material:** a `Material` prim under a sibling `Looks` scope, with a `UsdPreviewSurface` shader carrying `diffuseColor` (linear rgb), `opacity`, `metallic`, and `roughness`, bound with `rel material:binding`.
- **Visibility:** `token visibility = "invisible"` when hidden; `custom bool gama:locked`.
- **Light:** `inputs:color`, `inputs:intensity` (best effort), and `gama:intensity` (exact); spot adds `inputs:shaping:cone:angle`/`softness` plus `gama:innerAngle`/`gama:outerAngle`; point and spot add `gama:attenuationRadius`.
- **Camera:** `verticalAperture = 24` (mm), `focalLength = 12 / tan(fov/2)`, `clippingRange = (near, far)`, and `gama:fieldOfView` (exact).
- **Numbers** use `Float.description`, which gives the shortest round-trip form, so reading reproduces bit-identical `Float`s.

## Code

- **`SceneDocument` restore path (GamaAuthoring):** `public init(restoring records: [EntityRecord], roots: [EntityID], nextEntityID: EntityID) throws(AuthoringError)` runs `validate()`, plus a `public` memberwise `EntityRecord.init`. The reader needs this to keep ids exact. Mutation stays command-only; this only builds a whole validated value. File: `Sources/GamaAuthoring/SceneDocument.swift`.
- **New target `GamaUSD` (stdlib-only; added to `tools/check.sh`'s import ban):**
  - `USDAWriter.swift`: `public func usdaString(from: SceneDocument) -> String`, deterministic byte for byte.
  - `USDALexer.swift` and `USDAParser.swift`: a subset parser for prims, specifiers, typed attributes (scalars, tuples, arrays, strings, tokens), `rel`, `.connect` attributes, `(…)` prim metadata including `prepend apiSchemas`, and layer metadata with a `customLayerData` dictionary that has quoted keys. It tolerates `usdcat`'s formatting: blank lines, `(` metadata blocks, comments, `prepend apiSchemas`, and doc strings.
  - `USDAReader.swift`: `public func sceneDocument(fromUSDA: String) throws(USDError) -> SceneDocument`.
  - `USDError.swift`: `enum USDError: Error, Hashable { case syntax(line: Int, String), unsupported(line: Int, String), invalid(AuthoringError) }`.
- **`StudioModel`:**
  - `func replaceDocument(_:)`: builds a fresh `EditorSession(document:)`, calls `bridge.rebuild`, clears the selection, fires `onDocumentChange`.
  - `savedRevision` and `var hasUnsavedChanges`.
  - `func markSaved()`.
  - `EditorSession` gains `init(document:)` if it lacks one.
- **`StudioDocumentIO`** (GamaStudioEditor, Foundation): `save(model, to: URL) throws` and `open(URL) throws -> SceneDocument`, UTF-8 and atomic writes.
- **`StudioAppDelegate`:**
  - The File menu items above, and a `currentURL`.
  - `window.representedURL` and `isDocumentEdited` come from `hasUnsavedChanges`.
  - Before Open replaces unsaved changes, and in `applicationShouldTerminate` when quitting with unsaved changes, an `NSAlert` asks Save / Don't Save / Cancel.
  - A File menu joins the existing App menu in `main.swift`.
  - Errors show in an `NSAlert` and are never swallowed.
- **`main.swift`:** `--open <path>` and `--export <path>`.
  - `--export` runs headless: it reads (with `--open`) or builds the sample, writes, and exits 0, or 1 with the error on stderr.
  - It never constructs the ARView, the window, or `NSApplication`.

## Tests (Swift Testing; new `GamaUSDTests` target)

- The round trip is exact (`==`, including ids and `nextEntityID`) for:
  - `StudioModel.sampleScene()`;
  - `SampleScene`;
  - every `Primitive`;
  - every `LightKind`;
  - hidden and locked entities;
  - non-ASCII and colliding names;
  - an empty document;
  - several roots;
  - an entity with both a light and a camera (the component-child rule).
- The writer is deterministic: two writes are byte-identical, and a golden check pins the sample scene's USDA.
- The reader accepts `usdcat`-reformatted text: a checked-in fixture produced by `usdcat` from the golden file.
- Refusals carry a line number: unknown prim type, bad number, missing `gama:formatVersion`, duplicate `gama:id`, and a document that fails `validate()` (cycle or bad material) → `.invalid`.
- `StudioModel.replaceDocument` clears undo, redo, and selection, rebuilds the bridge (entity count matches), and `hasUnsavedChanges` tracks run, undo, and markSaved.
- Raise `MIN_TESTS` to the measured total.

## Gate additions (`tools/check.sh`)

- Import ban covers `GamaUSD`.
- A new USD stage:
  - `gama-studio --export <scratch>/sample.usda`;
  - `usdchecker` on it must print `Success!`;
  - `usdcat` it to a second file;
  - `gama-studio --open <that> --export <third>` must be byte-identical to the first export.
  - That comparison checks document equality, not `usdcat` text. `usdcat` output differs in bytes, but the writer is deterministic, so equal documents re-export identically.
- The stage fails closed if `usdchecker` is missing, and says so. It never skips silently.
